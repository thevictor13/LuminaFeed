## Context

The last 11 commits (`9f441ea` G0.1 → `cf264dc` admin seed) implement **Phase 0 — Groundwork** of `doc/plans/00-master-plan.md`: packages + test project, folder skeleton, domain model + EF persistence, admin authorization policy, typed configuration options, MailKit email infrastructure, RSS research, and DB seeding (feed catalogue + bootstrap admin).

A senior architecture review of this phase found the groundwork is **broadly solid** — GUID v7 is genuinely used and correctly paired with `ValueGeneratedNever()`; unique constraints exist where they matter; both seeders are idempotent; the admin password is Identity-hashed (never plaintext in the DB); the migration matches the fluent configuration exactly; and tests use real in-memory SQLite rather than the EF InMemory provider. However, a set of correctness, robustness, security-hygiene, portability, and documentation gaps remain. This plan remediates them **within Phase 0's scope only**.

**Explicitly out of scope (correctly deferred by the master plan, NOT defects):** `INotificationService`, `EmailNotificationService`, `SlackNotificationService`, RFC 8058 unsubscribe, feed polling/background service, and all public/admin UI. These are Phase 1–2 items and remain deferred. This plan does not build them.

**Decisions confirmed with the user:**
1. Remediation scope = **everything, including nits** (correctness + schema + security hygiene + encapsulation + SQL-Server portability + documentation).
2. Schema changes = **edit the existing `AddDomainModel` migration in place** (greenfield, `app.db` is gitignored/regenerated, no shared DB).
3. Committed dev secrets in `appsettings.Development.json` = **leave as-is**; only document that the Development overlay must never load in production.
