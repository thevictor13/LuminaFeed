## Context

This plan remediates a review of **Track C1** ("Full subscribe flow"), delivered in four commits on `phase-2c`
(`7859d5c` plan · `d4a8e67` service layer · `85faa00` dialog UI · `1ee2c44` docs). C1 turns the walking-skeleton
one-click email subscribe into the spec's full flow: a channel dialog with email + Slack switches, a validated and
`LastOrDefault`-prefilled Slack webhook, per-channel unsubscribe, and the red Unsubscribe state — Slack **delivery** is
deliberately deferred to C2.

**Verdict: C1 is a solid, well-tested, well-documented implementation.** The review found one real robustness bug, one
accessibility/consistency regression, one code smell, and a small set of test-coverage gaps — none block the feature,
all worth closing before the track is final.

Why it matters: the webhook bug lets a malformed URL reach the database and pollute the prefill that C2 will later
dispatch to; the a11y gap makes the app's most-used dialog worse for keyboard users than the admin dialogs; and the
untested branches (concurrency recovery, prefill tie-break) are exactly the ones that fail silently later.

## Review findings (ranked)

**F1 — Correctness (medium): an invalid Slack webhook can be persisted, and the prefill polluted.**
`SaveSubscriptionRequestValidator` gates **all** webhook rules on `.When(r => r.SlackEnabled)`. The dialog keeps
`form.SlackWebhookUrl` after the Slack switch is toggled off (the input just stops rendering). So *toggle Slack on →
type `https://evil.example.com/x` → toggle Slack off → Save* sends `(Email=true, Slack=false, "https://evil.example.com/x")`,
the validator **skips** the format/length rules, and the stored URL then surfaces as the `LastOrDefault` prefill on the
next feed. The same leak copies a valid prefill into a brand-new **email-only** subscription.

**F2 — Accessibility & duplication (medium): the dialog re-implements a modal without focus/Escape.**
`SubscribeDialog.razor` hand-rolls `.modal.show` + `.modal-backdrop` with **no initial-focus and no Escape-to-close**,
while the shared `Components/Shared/Modal.razor` (used by all three Admin pages) provides exactly those. Two modal
implementations that drift; keyboard users get a worse experience in the most-used dialog.

**F3 — Test gap (medium): the concurrency-recovery branch is unexercised.**
`SaveSubscriptionAsync`'s `catch (DbUpdateException)` re-loads the unique-index winner and applies the chosen channels.
No test forces a concurrent insert on `(UserId, FeedId)`.

**F4 — Code smell (low): the exception catch is broader than the race it recovers.**
`catch (DbUpdateException)` catches *any* update failure; recovery is only correct for a unique-index race (partly
guarded by the rethrow-when-no-winner path).

**F5 — Convention drift + test gap (low): `CreatedAt` bypasses `TimeProvider`.**
`Subscription.CreatedAt = DateTimeOffset.UtcNow` at construction, not the injected `TimeProvider` the project mandates.
Because the `LastOrDefault` prefill orders by `CreatedAt`, this drifts from convention and makes the tie-break among
multiple webhooks impossible to test deterministically (no wall-clock waiting allowed).

**F6 — Minor coverage (low):** the `LastOrDefault` tie-break among *multiple* stored webhooks and the dialog's rendering
of the fixed `AccountEmail` target are not asserted.

**Not defects (by design, verified):** Slack delivery absent (C2); the `SlackEnabled ⇒ SlackWebhookUrl` invariant
enforced in the flow not the entity/DB (master-plan decision — safe, since `SlackEnabled` only becomes true through the
validated `SaveSubscriptionAsync`); webhook retained when Slack toggles off (deliberate, for prefill); client-side
prefill ordering (SQLite can't `ORDER BY` a `DateTimeOffset`).

## Steps

One commit per step on `phase-2c`, each building with **0 warnings** and leaving **all tests green**. Reuse existing
idioms: the `CreateFeedRequest.cs` record+validator pattern, `ValidationResultExtensions.ToErrors()`, the shared
`Modal.razor`/`ErrorList.razor`, `FakeTimeProvider`, and the bUnit doubles in `SubscribeDialogComponentTests`.

### C1.R.0 — Save this plan
This file, committed under `doc/plans/`.

### C1.R.1 — Close the webhook leak (F1)
- **`Services/Subscriptions/SaveSubscriptionRequest.cs`** — split the webhook rules so *any* supplied webhook is
  format-checked regardless of the switch, while *required-ness* stays gated on Slack:
  ```csharp
  RuleFor(r => r.SlackWebhookUrl)
      .NotEmpty().WithMessage("A Slack webhook URL is required when Slack notifications are on.")
      .When(r => r.SlackEnabled);

  RuleFor(r => r.SlackWebhookUrl).Cascade(CascadeMode.Stop)
      .MaximumLength(Subscription.SlackWebhookUrlMaxLength)
      .Must(BeSlackWebhook)
      .WithMessage($"The webhook must be a Slack incoming webhook (it must start with {Subscription.SlackWebhookUrlPrefix}).")
      .When(r => !string.IsNullOrWhiteSpace(r.SlackWebhookUrl));
  ```
  (The service normalizes the URL to trimmed / null-if-blank *before* `ValidateAsync`, so `IsNullOrWhiteSpace` cleanly
  distinguishes "no webhook" from "some webhook".)
- **`Components/Shared/SubscribeDialog.razor` (`SaveAsync`)** — stop submitting a webhook when Slack is off, so the
  service keeps the *stored* value via its one-directional retention (no confusing hidden-field error; a new email-only
  row no longer copies the prefill): `var webhook = form.SlackEnabled ? form.SlackWebhookUrl : null;`.
- **Tests** — `SubscriptionServiceTests`: a non-Slack URL with **Slack off** is rejected (was silently stored);
  email-only + Slack-off + null webhook still succeeds and stores no webhook. `SubscribeDialogComponentTests`: toggling
  Slack off after typing a bad URL then Save persists an email-only row rather than erroring.

### C1.R.2 — Reuse the shared `Modal` for the dialog (F2)
- **`Components/Shared/Modal.razor`** — add `[Parameter] RenderFragment? Footer` (rendered as `<div class="modal-footer">`
  after the body when non-null) and `[Parameter] bool CloseDisabled` (gates the header close button and ignores Escape
  while set), preserving current focus/Escape/static-backdrop behaviour. Admin pages pass neither — unchanged.
- **`Components/Shared/SubscribeDialog.razor`** — render through
  `<Modal Visible="Visible" Title="@($"Subscribe to {FeedName}")" OnClose="CloseAsync" CloseDisabled="busy">`, moving the
  switches/webhook/`ErrorList` into `ChildContent` (inside the `EditForm`) and the Unsubscribe/Cancel/Save buttons into
  `<Footer>`. Keep all `@code`; delete the duplicate `.modal`/`.modal-backdrop`.
- **bUnit selector updates** — `Modal` emits its own `modal-title-{guid}` id, so tests asserting `#sub-dialog-title`
  (`SubscribeDialogComponentTests`, `HomePageComponentTests`, `FeedPageComponentTests`) target `.modal-title` text
  instead; add an Escape-closes assertion.
- **Browser check** — verify interactivity in a browser (scratchpad PuppeteerSharp probe, isolated instance), watching
  the console for circuit errors.

### C1.R.3 — Narrow the catch + test the recovery branch (F3, F4)
- **`Services/Subscriptions/SubscriptionService.cs`** — narrow both `catch (DbUpdateException)` sites to the unique-index
  race: `catch (DbUpdateException ex) when (ex.InnerException is SqliteException { SqliteErrorCode: 19 })`
  (SQLITE_CONSTRAINT), keeping the "no winner ⇒ rethrow" guard.
- **Test the recovery** — an `ISaveChangesInterceptor` test double that, on the **first** save inserting a
  `Subscription`, writes the conflicting `(UserId, FeedId)` row via a sibling context on the shared kept-open SQLite
  connection, so the original insert hits the unique index; assert `SaveSubscriptionAsync` returns `Result.Success` with
  a **single** row carrying the requested channels. Mirror a lighter version for `SubscribeByEmailAsync`.

### C1.R.4 — `CreatedAt` from `TimeProvider` + prefill/email coverage (F5, F6)
- **`Domain/Subscription.cs`** — make `CreatedAt` a settable property (drop the wall-clock default); update its XML doc.
- **`Services/Subscriptions/SubscriptionService.cs`** — inject `TimeProvider` into the primary constructor and set
  `CreatedAt = timeProvider.GetUtcNow()` at every insert site.
- **Tests** — construct the service with `FakeTimeProvider`; `GetSubscriptionForEditAsync` with **two** stored webhooks
  at distinct fake times on other feeds proves the prefill is the **most recent** one.
  `SubscribeDialogComponentTests`: the email switch label renders the supplied `AccountEmail`.
