# G0.3 — Domain Model + Persistence (plan)

## Context

G0.3 is the core groundwork prerequisite in the [master plan](./00-master-plan.md): it introduces the
LuminaFeed domain entities and their EF Core persistence so every later feature has data to work with. It is
**schema only** — seed data is loaded separately by G0.7 from
[`doc/research/rss-feeds.json`](../research/rss-feeds.json). The current `Data/` layer is the stock template:
`ApplicationDbContext : IdentityDbContext<ApplicationUser>` (empty body) and an empty
`ApplicationUser : IdentityUser`, with one Identity migration and a live `app.db`.

Field names are aligned with the G0.R research output (see
[`G0.R-rss-feed-research.md`](./G0.R-rss-feed-research.md)) so the G0.7 seeder maps 1:1:
`Category { name, description }`, `Feed { name, category, feedUrl, siteUrl, imageUrl?, description, popularity }`.

## Scope

- Extend `ApplicationUser` with an `IsAdmin` flag.
- Add domain entities: `Category`, `Feed`, `Subscription`, `Article`, sharing a GUID-v7 `EntityBase`.
- Register `DbSet`s + `IEntityTypeConfiguration`s; add the initial domain **migration**.
- Unit tests for the model (v7 ids, relationships, unique indexes, cascade behaviour).

Out of scope: seeding (G0.7), admin authorization (G0.4), any UI or services, actual polling/notifications.

## GUID v7 convention

`.NET 10` provides `Guid.CreateVersion7()`. New domain entities inherit:

```csharp
// Domain/EntityBase.cs
public abstract class EntityBase
{
    public Guid Id { get; set; } = Guid.CreateVersion7();
}
```

EF is configured with `Property(e => e.Id).ValueGeneratedNever()` for these keys so the client-generated v7
value is used (not EF's default v4 generator). **`ApplicationUser` is left on Identity's existing string key**
— it predates this rule and re-keying Identity is out of scope; `Subscription.UserId` is therefore a `string`
FK to `AspNetUsers.Id`.

## Persistence (`LuminaFeed/Data/`)

- `ApplicationDbContext`: add `DbSet<Category>`, `DbSet<Feed>`, `DbSet<Subscription>`, `DbSet<Article>`; in
  `OnModelCreating` call `base.OnModelCreating(builder)` first, then
  `builder.ApplyConfigurationsFromAssembly(typeof(ApplicationDbContext).Assembly)`.
- One `IEntityTypeConfiguration<T>` per entity in `Data/Configurations/`: key `ValueGeneratedNever`, required/
  maxlength, unique indexes, relationships + delete behaviour:
  - `Feed → Category`: **Restrict** (can't delete a category still holding feeds).
  - `Subscription → Feed`: **Cascade**; `Subscription → User`: **Cascade**.
  - `Article → Feed`: **Cascade**.
- Migration: `dotnet ef migrations add AddDomainModel` (installs `dotnet-ef` as a local tool if absent).
  Do **not** apply to the checked-in `app.db` here — the DB is recreated/seeded in G0.7.

## Tests (`LuminaFeed.Tests`)

Using a SQLite **in-memory** connection (`DataSource=:memory:`) + `EnsureCreated()`:
- `EntityBase.Id` is a **version-7** GUID (`id.Version == 7`) and non-empty.
- **Round-trip**: insert Category → Feed → Subscription + Article, save, reload with navigations.
- **Unique index**: a second `Subscription` for the same (`UserId`, `FeedId`) throws on save; likewise duplicate
  (`FeedId`, `ExternalId`) `Article`.
- **Cascade**: deleting a `Feed` removes its `Subscription`s and `Article`s; deleting a `Category` with feeds is
  blocked (Restrict).

3. `dotnet ef migrations list` shows `AddDomainModel`; generated migration reviewed for the four tables,

## Decisions to confirm

1. **Include the three polling-cache columns (`ETag`, `LastModified`, `LastPolledAt`) on `Feed` now** (nullable,
   populated later by C4) — recommended, to avoid a second migration when C4 lands. Alternative: defer to C4.
2. **Adopt `Article.ExternalId` + unique (`FeedId`, `ExternalId`) now** — resolves the master plan's open
   "article identity/de-dup" question at the schema level (guid-or-link). Recommended.
3. **`Description` nullable** on both `Category` and `Feed` (research supplies values, but admin edits in A1/A2
   may not) — recommended.
