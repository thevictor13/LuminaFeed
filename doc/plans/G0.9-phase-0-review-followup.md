## Findings addressed

1. **Plain-text email alternative.** `IdentityEmailSender` sent HTML-only (`EmailMessage.TextBody` never set). Added a plain-text counterpart to all three emails (confirmation, reset link, reset code); `MailKitMailSender.BuildMessage` already forwards `TextBody` to `BodyBuilder`, so no transport change.
2. **Email encoding consistency.** `IdentityEmailSender` interpolated the fallback link anchor and reset code into the trusted `bodyHtml` **raw**, bypassing `EmailLayout`'s encoding. Now encoded with `System.Text.Encodings.Web.HtmlEncoder.Default` (BCL — no new package).
3. **Test & doc hardening.** Added a direct-context `Model_HasNoPendingChanges_AgainstMigrationSnapshot` test (`DomainModelTests`) asserting `!ctx.Database.HasPendingModelChanges()` — the real drift guard, since `HostBootTests` legitimately suppresses `PendingModelChangesWarning` (a WAF false positive). Added email tests for the plain-text alternative and for HTML-encoding a hostile link. Fixed two doc nits in `configuration-options.md` (only `Host`/`HmacSecret` are empty in base config, not all of `Smtp`) and `email-infrastructure.md` (documents the plain-text + encoding behaviour).
4. **Admin claim-staleness forward guard.** Documented on the **A3** master-plan item that toggling `IsAdmin` must be followed by `UserManager.UpdateSecurityStampAsync` for the cookie-baked admin claim to refresh. No code change.
5. **Deferred template-UI cleanup, tracked.** Recorded as an **S2** checklist in `00-master-plan.md`: delete `Components/Pages/{Counter,Weather,Auth}.razor`, replace `Home.razor`'s placeholder, drop the Counter/Weather/Auth links in `NavMenu.razor`, and remove the dead `System.Net.Http[.Json]` imports in `_Imports.razor`.
