# G0.R — RSS Feed Research (plan & outcome)

## Context

**G0.R is the first Phase-0 task in the [master plan](./00-master-plan.md) and gates the rest.** Three data
artifacts flow out of it into later code:

1. The **category set** — replaces the spec's illustrative list (World News / Markets / Weather / Breaking News).
2. The **curated feed list** — the admin-curated `Feed` seed rows.
3. The **fixed `Popularity` figure per feed** — a stored integer driving the public feed list's default ordering.

Consumers: **G0.3** (domain model — `Category`/`Feed` fields must line up with this output) and **G0.7**
(seed data — loads the JSON directly). The codebase is greenfield, so this deliverable defines those field
names. IDs are GUID v7 generated at seed time, so the data keys categories by **name** and feeds reference
their category by **name** (no hardcoded GUIDs). This is a non-code research spike; output is checked-in data.

## Deliverables (in `doc/research/`)

| File | Role |
|------|------|
| [`doc/research/rss-feeds.json`](../research/rss-feeds.json) | **Canonical, machine-readable.** Source of truth for the G0.7 seeder. |
| [`doc/research/rss-feeds.md`](../research/rss-feeds.md) | Human-readable companion: category summary, feeds-by-category tables, verification evidence, methodology. |

### `rss-feeds.json` shape
Top-level `{ generatedOn, categories[], feeds[] }`. Each feed carries the seed fields G0.3 adopts:
`name`, `category` (matches a `categories[].name`), `feedUrl`, `siteUrl`, `imageUrl` (nullable), `description`,
`popularity` (distinct fixed int, higher = more popular). Per-feed verification evidence lives only in the `.md`.

## Approach (as executed)

1. Drafted **10 categories** and sourced a large candidate list of well-known publisher RSS/Atom endpoints.
2. **Live-validated** every candidate with a PowerShell probe (browser UA): kept only **HTTP 200** responses
   that parse as RSS/Atom/RDF with ≥1 item. Captured **ETag**/**Last-Modified** support (for C4 polling),
   per-item image presence, and resolved a feed image (RSS `<image>`/Atom logo → scraped `og:image` → null).
3. Dropped feeds returning non-200, HTML instead of a feed, or blocking automation (403/406/429/202).
4. Assigned **popularity** from rough real-world prominence, made globally unique for deterministic sort.
5. Emitted `rss-feeds.json` (seed fields) and `rss-feeds.md` (with the verification-evidence table).

## Verification (done)
- JSON parses; every `feeds[].category` exists in `categories[]`; all required fields present;
  `popularity` and `feedUrl` values unique. → **PASS**.
- Scale: most categories exceed the 5-card display (exercises "+5 more"); **Technology = 36** exceeds the
  public **30-cap** category filter (exercises "+30 more").

## Outcome

**Status: COMPLETE.** 115 validated feeds across 10 categories (World News 11, Breaking News 9, Politics 7,
Business & Markets 10, Technology 36, Science 12, Health 7, Sports 7, Entertainment & Culture 11, Weather 5).
101/115 resolved a feed image. Ready for consumption by **G0.3** (schema alignment) and **G0.7** (seeder).

## Notes for downstream tasks
- **G0.3**: name `Feed` fields `Name`, `FeedUrl`, `SiteUrl`, `ImageUrl` (nullable), `Description`, `Popularity`
  (int); `Category.Name` (unique). Keep `ImageUrl` nullable — 14 feeds have no image.
- **G0.7**: deserialize `rss-feeds.json`; upsert categories first (by name), then feeds referencing them; generate
  GUID v7 IDs at insert. `&` in the JSON is standard escaping for `&` and decodes normally.
- Weather has only 5 feeds — RSS is scarce there; acceptable (matches the spec's own illustrative example set).
