## Context

The last six commits on `phase-1` (`8190ee3` plan → `1449769` S1 → `aca33d9` S2 → `f9f6171` S3 → `7e4523b` S4 → `5fc40c4` S5) implement **Phase 1 — the walking skeleton** of `doc/plans/00-master-plan.md`: admin create/list for categories and feeds, the public card list, email-only subscribe/unsubscribe, minimal feed polling (fetch → parse → persist) and the first `INotificationService` (email digest). ~4,900 lines across 64 files, including 15 new test files (200 tests).

A senior architecture review of those commits (this session, with an independent second pass) finds the skeleton **sound and honestly scoped**: the definition of done is genuinely met end-to-end through the real host (`WalkingSkeletonTests`); services are thin `ErrorOr` + FluentValidation classes over `IDbContextFactory`; the background loop cannot take the host down; feed content is HTML-encoded and the parser is XXE-safe; DI lifetimes are correct; `[PersistentState]` is used properly; the user id never comes from the client; deliberate Phase-2 deferrals are recorded rather than hidden.

What it also found: **one flow-breaking bug outside the six commits' diff but on the path S3 claims** (self-registration can never be confirmed), a handful of correctness edge cases, design debt that Phase 2 would otherwise build on, spec gaps in the return-URL flow, one real test flake mechanism, an untested interactive path, and doc drift. This plan fixes those within Phase 1's scope and re-baselines the master plan so Phase 2 plans neither redo S4/S5 work nor discover their prerequisites mid-way.
